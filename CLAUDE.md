# Lemokey P1 Pro — своя прошивка QMK

> Форк Keychron, ветка `wireless_playground`. Апстрим не трогаем, всё своё — в раскладке `custom`.

---

## Что сделано

Подсветка, своя для каждого слоя. Перешёл на слой — горят те клавиши и теми цветами,
которые для этого слоя заданы. Настраивается мышкой в браузере, без перепрошивки.
Ни Keychron Launcher, ни VIA так не умеют.

Слой, для которого своя раскраска не включена, светится как раньше — штатным эффектом.
Ничего не ломается по умолчанию.

## Железо

```
Клавиатура:  Lemokey P1 Pro, ANSI, с энкодером
Плата:       keyboards/lemokey/p1_pro/ansi_encoder/
Цель:        lemokey/p1_pro/ansi_encoder:custom
МК:          WB32F3G71RCT6 (ARM Cortex-M3)
Флеш:        256 КБ, занято ~75 КБ
Оперативка:  36 КБ, занято ~28 КБ
EEPROM:      2 КБ внешняя по I2C — самый дефицитный ресурс
Светодиоды:  81, южное расположение
Матрица:     6 строк × 15 колонок
USB:         362d:0303 рабочий режим, 342d:dfa0 бутлоадер
```

### Куда уходит EEPROM

| что | байт |
|---|---|
| служебное QMK | 37 |
| наша подсветка | 416 |
| заголовки VIA | 4 |
| раскладка (4 слоя × 6 × 15 × 2) | 720 |
| энкодер по слоям | 16 |
| **осталось макросам** | **855** |

Флеша при этом свободно под 180 КБ. Отсюда правило: **тяжёлое держим во флеше,
в EEPROM кладём только то, что нужно менять без перепрошивки.**

---

## Важно знать про исходники

**Прошивки V1.1.0 в открытом доступе нет.** P1 Pro существует только в ветке
`wireless_playground`; в остальных восьми ветках репозитория Keychron каталога платы нет
вовсе. Код в ветке не менялся с момента добавления платы, `device_version` там `1.0.1`,
и per-key RGB в нём отсутствует полностью.

Стоковая V1.1.0 от 24.07.2025 per-key RGB умеет и весит 86 536 байт против 73 000
у сборки из репозитория — те самые ~13,5 КБ невыложенного кода.

Практическое следствие: **наши сборки представляются как `v1.0.1`.** Отличать свою
прошивку от стоковой нужно **по дате сборки** в ответе на raw HID `0xA1`, а не по номеру
версии.

## Как устроена подсветка

### Хранение

Всё в `keymaps/custom/layer_rgb.c`, структура кладётся в EEPROM через
`EECONFIG_USER_DATA_SIZE` (416 байт, задан в `keymaps/custom/config.h`).

```
custom        1 байт    бит N поднят — у слоя N своя раскраска
used          1 байт    сколько цветов занято в палитре
palette      48 байт    16 цветов HSV
base        243 байта   слой 0 полными цветами
packed      123 байта   слои 1-3 номерами палитры, по полбайта на светодиод
```

Слой 0 хранится полными цветами, потому что туда пишет лаунчер Keychron и урезать его
нельзя. Слои 1-3 упакованы: на слое редко больше пяти-шести цветов, а номер влезает
в четыре бита. Так вышло 416 байт вместо 973 — освободившиеся 557 достались макросам.

Наружу это **не видно**: и лаунчер, и красилка шлют обычные HSV. Прошивка сама ищет цвет
в палитре, заводит новый, пока есть места, а когда все 16 заняты — подбирает ближайший.
Перед записью в EEPROM палитра пересобирается только из цветов, которые реально
встречаются (`palette_compact`), иначе следы старых правок забили бы все места.

### Отрисовка

- **слой 0** — эффект `PER_KEY_RGB` из `keymaps/custom/rgb_matrix_user.inc`. Идёт следом
  за 23 штатными, то есть получает номер 23 — ровно тот, который лаунчер включает,
  когда жмёшь Per Key RGB
- **слои 1-3** — `rgb_matrix_indicators_advanced_user`, кладёт цвета поверх любого эффекта.
  Если бит слоя в `custom` не поднят, функция сразу выходит и не вмешивается

## Протокол 0xA8

Снят дампом с живого лаунчера через WebHID и **воспроизведён байт в байт** — лаунчер
не отличает нашу прошивку от стоковой. Команды `0x01`-`0x0A` родные Keychron
(сверять с `keyboards/keychron/common/rgb/keychron_rgb.c`), `0x40`-`0x43` наши.

```
a8 01                                версия протокола
a8 02                                сохранить в EEPROM
a8 03                                настройки индикаторов -> 02 00 ff 00 ff
a8 04 <disable> <h> <s> <v>          задать индикаторы
a8 05                                сколько светодиодов -> 51 (81)
a8 06 <строка> ff ff ff              карта строки матрицы -> 15 номеров, ff где нет клавиши
a8 07                                режим per-key
a8 08 <тип>                          задать режим
a8 09 <от> <сколько>                 прочитать цвета слоя 0
a8 0a <от> <сколько> <h s v>...      записать цвета слоя 0

a8 40                                маска слоёв со своей раскраской
a8 41 <маска>                        задать маску
a8 42 <слой> <от> <сколько>          прочитать цвета слоя
a8 43 <слой> <от> <сколько> <hsv>... записать цвета слоя
```

Ответ: `a8 <команда> <00 успех / 01 отказ> <данные...>`. За пакет проходит не больше
девяти цветов — в 32 байта больше не влезает.

Раскладку красилка читает штатной командой VIA `0x12` (dynamic keymap buffer),
смещение слоя = `слой × 6 × 15 × 2`.

### Единственная правка апстрима

`keyboards/lemokey/common/lemokey_raw_hid.c` — приём `0xA8`, шесть строк под
`#ifdef LAYER_RGB_ENABLE` (флаг ставится в `keymaps/custom/rules.mk`). Без неё команда
проваливается в `default` и молча отбрасывается: у Lemokey, в отличие от Keychron,
раздел `0xA8` не обрабатывается вовсе.

Хук `via_custom_value_command_kb` у Lemokey свободен, но `via_command_kb` занят сильным
определением — переопределить его из раскладки нельзя, отсюда и правка в общем файле.

## Команды

```bash
# окружение (один раз)
sudo apt install -y gcc-arm-none-eabi binutils-arm-none-eabi libnewlib-arm-none-eabi \
                    build-essential pipx cmake libusb-1.0-0-dev pkg-config
pipx install qmk
pipx inject qmk appdirs argcomplete colorama pygments pyserial pyusb pillow
git submodule update --init --recursive

# сборка
qmk compile -kb lemokey/p1_pro/ansi_encoder -km custom

# прошивка: сторож ждёт бутлоадер и сам всё делает
bash tools/flash_custom.sh
```

`wb32-dfu-updater_cli` в репозиториях Pop!_OS нет, собирается из исходников
[WestberryTech](https://github.com/WestberryTech/wb32-dfu-updater), лежит в `~/.local/bin`.
Штатная команда QMK для этой платы: `wb32-dfu-updater_cli -D файл.bin && wb32-dfu-updater_cli -R`.

### Вход в бутлоадер

Выдернуть кабель, зажать **Esc**, воткнуть кабель не отпуская. Боковой переключатель
должен стоять в положении **Cable**. Запасной путь — кнопка сброса на днище под пробелом.

Клавиатура в этот момент перестаёт быть клавиатурой, поэтому **все скрипты запускаются
заранее и работают без участия человека**, а инструкция пишется до, а не после.

## Красилка

```bash
cd keyboards/lemokey/p1_pro/ansi_encoder/keymaps/custom/tools
python3 -m http.server 8777 --bind 127.0.0.1
```
Открыть в **Chrome**: `http://127.0.0.1:8777/paint.html`

Локальный сервер обязателен: WebHID не работает с файлом, открытым напрямую, и его нет
в Firefox. Если лаунчер Keychron открыт — закрыть вкладку, устройство достаётся тому,
кто подключился первым.

Умеет: выбор слоя, покраска мышкой (правая кнопка гасит), выключатель своей раскраски
для слоя, кнопка «Только назначенные» — читает раскладку из клавиатуры и подсвечивает
клавиши по типу действия. Подписи на схеме реальные, из твоей раскладки.

## Грабли, на которые уже наступили

**Килобайт на стеке.** Штатная `eeconfig_init_user_datablock()` в ядре QMK заводит
временный буфер размером со весь блок **на стеке**. При блоке в 973 байта прошивка падала
на первом старте с чистым EEPROM — не поднимался третий USB-интерфейс, и вместе с ним
пропадали громкость на энкодере, мышь и системные клавиши. В журнале ядра это выглядит
как `usbhid ...:1.2: can't add hid device: -110`. Функция помечена `weak`, поэтому
заменена своей в `layer_rgb.c` — пишем из готовой структуры, стек не трогаем.

**Проверять журнал ядра после каждой прошивки.** То, что устройство вернулось на шину
под своим VID:PID, ничего не доказывает — интерфейсы могут не подняться. Сторож
`flash_custom.sh` проверяет это сам и докладывает.

**EEPROM обнуляется при каждой прошивке.** Раскладка возвращается к стоковой, покраска
слетает. Раскладку восстанавливать из сохранённого json в лаунчере, покраску — кнопкой
«Только назначенные» или `tools/paint_assigned.py`.

**Firefox не годится** — в нём нет WebHID вообще.

```
reference/p1_pro_ansi_encoder_v1.1.0_2507241646.bin   официальная V1.1.0
reference/dump_from_device_*.bin                      256 КБ, снято с этого экземпляра
```

Путь отката проверен на живой клавиатуре: уходит в DFU, принимает прошивку, возвращается
в работу. Чтение флеша не защищено, дамп снимается ключом `-U` без снятия защиты
(снимать её нельзя — на WB32 это обычно стирает флеш).

## Правила работы

1. **Апстрим не трогаем.** Правки только в `keymaps/custom/`. Единственное исключение —
   шесть строк в `lemokey_raw_hid.c`, и те под `#ifdef`. Понадобилось больше — сначала
   объяснить зачем и получить добро.
2. **Проверка — сборка.** После каждой правки `qmk compile`. Прошивка только по явной
   просьбе.
3. **Беспроводной режим не ломать.** Дефайны Keychron в `config.h` и `post_rules.mk`
   не удалять без нужды. `EXTRAKEY_ENABLE` не отключать — без него отвалится громкость
   на энкодере.
4. **EEPROM дороже флеша.** 2 КБ против 256. Прежде чем класть что-то в EEPROM — посчитать
   и прикинуть, нельзя ли упаковать или вычислять на лету.
5. **Комментарии и общение по-русски**, кратко, по делу. Без пересказа кода и секционных
   разделителей.
6. **Владелец репозитория C не знает** — объяснять человеческим языком: что делает код,
   что он увидит на клавиатуре, чем рискуем.
7. **Перед прошивкой** сохранить раскладку из лаунчера в json.
