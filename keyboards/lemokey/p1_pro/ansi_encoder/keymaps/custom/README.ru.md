# Подсветка по слоям для Lemokey P1 Pro

[English](README.md) · **Русский**

Пер-клавишная подсветка, которая хранится **отдельно для каждого слоя** и правится
мышкой в браузере — без пересборки и перепрошивки. Ни Keychron Launcher, ни VIA так
не умеют: там доступны только яркость, эффект, скорость и один общий цвет.

Keychron Launcher при этом работает как работал — раскладка, слои, макросы, эффекты
и его собственная пер-клавишная покраска базового слоя. Прошивка говорит на его
протоколе байт в байт.

---

## Что получается

Перешёл на слой — он светится так, как ты его нарисовал. Слои, до которых ты не
добрался, продолжают показывать обычный эффект из лаунчера: по умолчанию ничего
не меняется.

Типичный сценарий: на слое Fn горят только те клавиши, которым что-то назначено,
и цветом по смыслу — медиа зелёным, Bluetooth и батарея голубым, управление подсветкой
синим, прочее белым, а неназначенное потушено.

Страница-красилка читает раскладку прямо из клавиатуры, поэтому после перестановки
клавиши в лаунчере подсветка едет за ней — одна кнопка, и картинка пересобрана.

## Железо

| | |
|---|---|
| Клавиатура | Lemokey P1 Pro, ANSI, с энкодером |
| Микроконтроллер | WB32F3G71RCT6, ARM Cortex-M3 |
| Флеш | 256 КБ, занято ~75 КБ |
| Оперативка | 36 КБ, занято ~28 КБ |
| EEPROM | 2 КБ, внешняя по I2C |
| Светодиоды | 81 |
| Матрица | 6 строк × 15 колонок |

## Что нужно

- окружение QMK с ARM-компилятором (`gcc-arm-none-eabi`)
- [`wb32-dfu-updater_cli`](https://github.com/WestberryTech/wb32-dfu-updater) — в
  репозиториях дистрибутивов его обычно нет, собирается из исходников
- Chrome или другой браузер на Chromium для красилки: в Firefox нет WebHID

## Сборка

```bash
qmk compile -kb lemokey/p1_pro/ansi_encoder -km custom
```

## Прошивка

Выдернуть кабель, зажать **Esc**, воткнуть кабель не отпуская. Боковой переключатель
должен стоять в положении **Cable**. Есть и кнопка сброса — на днище под пробелом.

В бутлоадере клавиатура перестаёт быть клавиатурой, поэтому скрипт сам дожидается
устройства и после запуска ничего не спрашивает:

```bash
bash tools/flash_custom.sh
```

Он заливает прошивку, возвращает сток, если запись сорвалась, и проверяет журнал
ядра — поднялись ли все три USB-интерфейса. Одного лишь возвращения устройства на шину
недостаточно: интерфейсы могут не встать, и тогда молча отвалятся громкость на энкодере,
мышь и системные клавиши.

**Прошивка стирает EEPROM.** Раскладка возвращается к стоковой, покраска слетает.
Сохрани раскладку из лаунчера заранее; подсветку потом можно вернуть одной кнопкой.

## Красилка

```bash
cd tools
python3 -m http.server 8777 --bind 127.0.0.1
```

Открыть в Chrome `http://127.0.0.1:8777/paint.html`. Локальный сервер обязателен:
WebHID не работает со страницей, открытой из файла напрямую.

- выбираешь слой, левая кнопка красит, правая гасит
- **«Только назначенные»** читает раскладку и подсвечивает всё, чему на этом слое
  что-то назначено
- галочка у слоя — главный выключатель: снял, и слой снова светится обычным эффектом
- до нажатия **«Записать и сохранить»** в клавиатуру ничего не уходит

Вкладку Keychron Launcher лучше закрыть: устройство достаётся тому, кто подключился
первым.

## Как это хранится

416 байт EEPROM:

| поле | байт | что это |
|---|---|---|
| `custom` | 1 | бит N поднят — у слоя N своя раскраска |
| `used` | 1 | сколько цветов занято в палитре |
| `palette` | 48 | 16 цветов HSV |
| `base` | 243 | слой 0, полными цветами |
| `packed` | 123 | слои 1–3, номера палитры, полбайта на светодиод |

Слой 0 хранится полными цветами, потому что туда пишет лаунчер и урезать его нельзя.
Слои 1–3 упакованы: на слое редко бывает больше пяти-шести цветов, а номер влезает
в четыре бита. Вышло 416 байт вместо 973, освободившиеся 557 достались макросам.

Снаружи это не видно: и лаунчер, и красилка шлют обычные HSV. Прошивка сама ищет цвет
в палитре, заводит новый, пока есть места, а когда все 16 заняты — подбирает ближайший.
Перед записью в EEPROM палитра пересобирается только из тех цветов, которые реально
встречаются, иначе следы прошлых правок забили бы все места.

## Протокол

Раздел `0xA8`. Команды `0x01`–`0x0A` — родные Keychron, сняты дампом с лаунчера через
WebHID и повторены точно; `0x40`–`0x43` — добавленные, с номером слоя.

```
a8 01                                 версия протокола
a8 02                                 сохранить в EEPROM
a8 03                                 настройки индикаторов
a8 04 <disable> <h> <s> <v>           задать индикаторы
a8 05                                 сколько светодиодов -> 0x51
a8 06 <строка> ff ff ff               строка матрицы -> 15 номеров, ff где нет клавиши
a8 07 / a8 08 <тип>                   режим per-key
a8 09 <от> <сколько>                  прочитать цвета слоя 0
a8 0a <от> <сколько> <h s v>...       записать цвета слоя 0

a8 40 / a8 41 <маска>                 у каких слоёв своя раскраска
a8 42 <слой> <от> <сколько>           прочитать цвета слоя
a8 43 <слой> <от> <сколько> <hsv>...  записать цвета слоя
```

Ответ: `a8 <команда> <00 успех / 01 отказ> <данные...>`. За пакет проходит не больше
девяти цветов — в 32 байта больше не влезает.

Раскладка читается штатной командой VIA `0x12`, смещение слоя — `слой × 6 × 15 × 2`.

## Правки вне своей раскладки

Одна: шесть строк в `keyboards/lemokey/common/lemokey_raw_hid.c` под
`#ifdef LAYER_RGB_ENABLE`. У плат Lemokey раздел `0xA8` не обрабатывается вовсе,
и без этой вставки команда молча отбрасывалась бы. Всё остальное живёт внутри раскладки.

## Что стоит знать

Исходники прошивки V1.1.0 не публиковались. P1 Pro существует только в ветке
`wireless_playground`, а код там старше — `device_version` показывает `1.0.1`,
пер-клавишного RGB нет вовсе. Поэтому сборки отсюда представляются как `v1.0.1`:
отличать свою прошивку нужно по **дате сборки** в ответе на `0xA1`, а не по номеру версии.

Штатная `eeconfig_init_user_datablock()` в QMK заводит буфер размером со весь
пользовательский блок **на стеке**. При таком блоке он переполняется, и прошивка падает
на первом старте с чистым EEPROM: третий USB-интерфейс не поднимается, вместе с ним
пропадает громкость на энкодере. Функция помечена `weak` и здесь заменена своей.
